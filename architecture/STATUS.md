# 主干实现状态（2026-10-29）

本文区分实际缺陷、能力缺口和运行边界，不将所有未实现能力都当成基础插件开发的前置条件。接口定义见 [PLUGINS.md](PLUGINS.md)。

## 已确定的职责与兼容要求

主干限定为模型 API 配置、LLM 人格与记忆、插件运行与调用、日志与权限、统一配置和管理入口。业务能力及策略归插件。主干与插件必须独立升级；主干重构不得要求旧插件同步修改，插件开发不得改主干或无关插件。完整硬约束见 `AGENTS.md` 和 [PLUGINS.md](PLUGINS.md)，不得再把插件功能列为主干必做项。

已加入冻结插件样本和 `test:compat`；现有旧插件验收改为读取冻结副本，不再随着可维护示例一起变化。摘要校验防止无意修改样本，规范禁止连同摘要和断言一起改写来掩盖不兼容。这是首份兼容基线，不是完整 API 版本协商、历史宿主矩阵或进程隔离的实现。CI 工作流因现有凭据缺少 GitHub workflow 权限未能部署，仅保存在本机 `.artifacts/plugin-compatibility.workflow.yml`；远端没有新增自动检查或合并保护。

本次规则与验收调整在本机通过56项专项测试及TypeScript检查，全部使用临时数据和模拟模型。未修改生产运行代码、正式配置或记忆；不需要重启服务。

## 本次审查确认并修复

1. 插件新建会话没有遵守记忆恢复屏障。现在新建会话经过Sessions生命周期登记，在进入及提交记忆写队列时重新检查维护状态和取消信号，避免恢复期间或排队后绕过保护。
2. 插件HTTP处理器收到取消后，响应关闭不代表任务清理已完成。现在Web关闭跟踪并等待已接收的处理器，核心关闭同时等待已经开始的插件事件处理，然后等待记忆队列。

修复前用独立模拟脚本复现两项。修复后相关43项测试通过，包括新增维护并发、网页任务与事件清理回归；TypeScript检查通过。不使用真实模型或正式记忆。

## 与已定职责有关的实现限制

| 项目 | 当前事实 | 实际影响 |
| --- | --- | --- |
| 统一模型配置的插件接入 | 模型用途与协议仍在核心中列举，插件可查询模型元数据及调用对话，但没有通用的非对话连接使用接口 | 需要保证插件能使用用户配置；不据此把语音、图像、重排序或向量召回实现塞进主干 |
| 接口与内部实现尚未完全分开 | `Context` 部分服务为 any；logger/approval 等对象及部分返回结构仍与实现共用 | 文档和类型未形成完整的稳定边界，不能承诺任意内部重构都不影响插件；应在提供方保持契约，不能推给插件改写 |
| 插件API版本兼容检查 | manifest.version被读取，没有requiresApi/minCore版本校验与兼容拒绝机制 | 升级后不兼容插件可能加载后才报错，无法提前给出准确兼容提示 |
| 完整模块热重载 | 入口import增加缓存参数，静态import的子模块可能仍取ESM缓存 | 修改插件lib后点重载可能继续运行旧实现；当前可靠方式是重启进程 |
| 审批流程 | off/full可用；ask中按工具规则直接放行的调用可用，需要审批的调用没有待审批队列和批准界面 | 不能将ask描述为已完成的交互审批；完全执行权限不依赖此能力 |
| 渠道职责偏厚 | 现有核心还负责外部投递、回执与重试 | 后续收敛到插件或可复用辅助库时必须保留旧公开入口与行为，不能直接删除接口或要求渠道插件重写 |
| 故障隔离不完整 | 插件同进程执行；受管理异常可处理，但死循环、OOM、process.exit 不受此保护 | 目前不满足任意插件故障都不影响宿主的强隔离要求，不能用现有异常测试冒充完整隔离 |

故障要求已明确为“主干可切割故障插件并继续工作”。现有工具/页面入口会在停用时撤销，加载和事件异常已有隔离；但等待不返回的工具任务、Web handler 或事件 handler 仍缺乏完整的有界退出机制，同进程同步卡死也不能由主干单独终止。因此“发现故障后可靠切割”的完整要求尚未实现。该结论来自源码核查，本次只补充验收标准，未改运行代码，也未把旧测试结果当作新机制的验证。

## 运行和验证边界

- 会话历史按文件读取，独立渠道回执保留在全局索引中并持续增长；尚无大量历史/长时间高吞吐运行的容量结论。需要按实际规模评估索引和分段读取，不能直接许诺长期性能。
- 插件同进程运行；取消是协作机制，不能强杀不返回的插件代码，也不能撤回已发生的外部发送。业务超时、重试与预算由插件自行决定。
- 本轮验证使用模拟插件、本机HTTP和已有回归；尚未用真实QQ/B站等插件做持续联调。没有实际连接时不声称平台行为已经验证。
- 插件直接调用模型的usage可以自行读取；主干没有插件用量汇总展示，也不统一管理插件预算。

文本交流、人格切换、记忆、工具、设置/页面入口和渠道收发已有可用链路。向量召回、语音/图像、具体平台、意图和主动行为由插件实现，不是主干功能缺口。现有兼容验收不等于已经实现全部类型隔离、版本兼容和运行故障隔离；不得宣称这三个方面全部完成。
