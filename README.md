# WhaleLife / whalecore

本地机器人核心：OpenAI 兼容模型、人格、流式 Web 聊天、可扩展的文件记忆、三路日志和 cordis 插件树。

架构与开发说明：[插件扩展契约](architecture/PLUGINS.md) · [记忆系统](architecture/MEMORY.md) · [通用渠道](architecture/CHANNELS.md)。这些公开文档说明实际实现、调用成本、扩展契约与边界，不包含本机私有资料。

## 启动

1. 安装 Node.js 24，或将官方 Windows x64 ZIP 解压到 `runtime/node-v24.22.1-win-x64/`（本机已配置）。
2. 用 Node 24 的 npm 执行 `npm ci`。本机依赖已安装。
3. 首次使用时将 `config.example.json` 复制到 `config/config.json`。本机已有私有配置，不要覆盖。
4. 双击 `start.bat`，打开 <http://127.0.0.1:9270>，进入控制台，在「模型服务」选择「对话」或「嵌入」并新增配置，填写服务地址、Key 和实际模型名称。勾选「使用此配置」或到「使用配置」中明确选择。

在启动窗口按 Ctrl+C 优雅退出。控制台保存的模型配置从下一次请求生效；端口、权限、人格文件路径等其他配置修改后重启。默认仅监听本机；局域网监听必须配置 `web.lan_enabled: true` 和 `web.password`。

## 模型控制台

「记忆管理」可给会话改名、搜索名称，或将档案设为当前会话继续聊天。删除会话会弹出一次确认，相关记录及摘要移入 `memory/trash/`，共享事实保留；删除当前会话后自动开始空会话。回复进行中的会话不能删除。

「记忆管理 → 当前会话上下文」可设置短期时间窗口、短期保底消息数和历史预算，独立开关历史注入、短期压缩、长期认知整理与共享事实，并选择当前人格版本或整段会话历史。默认 7 天、至少 100 条：只有早于 7 天且超出最近 100 条的消息才进入长期范围；一个月仅 20 条或一天 300 条都全部属短期。设置按会话保存，下轮请求生效。历史预算只控制注入内容的裁剪，不决定长期归类；实际占用单独使用最近一次模型请求返回的输入与输出 token 总数除以上下文上限显示，不累计历次请求。旧会话或服务没有返回用量时显示暂无统计。模型上限优先使用该模型手动填写的值，否则读取模型列表的 `context_window`；服务未提供时可在「模型服务 → 当前模型设置 → 模型上下文上限」填写。

侧栏按概览、模型服务、使用配置、人格配置、聊天测试、插件管理、运行日志组织。模型服务旁的数字只统计已启用、类型已接入且配置有效的模型，不计待修复记录。

人格页可新建或编辑名称、专用模型和人格内容，使用一个保存动作统一提交。“保存”仅保留配置；“保存并启用”指定为当前 Web 聊天人格，并保留当前会话及聊天记录。内容保存在人格文件，下一次请求读取；当前人格也可点击“开始新会话测试”，避免旧对话影响观察。聊天标题与头像跟随当前人格。插件管理仅显示扩展插件。页面、样式与请求逻辑拆分在 `core/ui/`，新增页面可接入 `app.js` 的页面注册表。

「模型服务」按模型类型隔离列表。左侧选择一条模型配置，右侧直接编辑完整连接设置。新增时选择对应服务类型；配置名称由用户命名，实际模型名称以服务商文档为准，两者不能混淆。DeepSeek 对话连接不会出现在嵌入服务列表中。历史误配保留为「待修复」，不能被绑定或调用。

支持 OpenAI 兼容协议，以及百炼 DashScope 原生嵌入协议。对话接口为 `/chat/completions`，OpenAI 兼容嵌入接口为 `/embeddings`；DashScope 原生嵌入接口为 `/services/embeddings/text-embedding/text-embedding`。API 根地址可编辑，包含服务要求的版本前缀，并与 Key 的地域一致。

「测试」与「自动检测」使用当前表单中的设置，不会自动保存。嵌入维度记录预期向量长度，自动检测会读取实际返回值并回填，需点击保存；普通测试发现维度不一致会报错。若模型支持缩减输出维度，可在高级参数中填写 OpenAI 的 `dimensions` 或 DashScope 的 `dimension`，随后重新检测。超时（1–600 秒）和可选 HTTP/HTTPS 代理会实际作用于模型请求；代理地址不支持内嵌认证信息。

「使用配置」分别选择对话、Embedding 等用途，并在「人格配置」区域选择当前聊天人格，点击一次保存即可同时生效。切换人格后保持当前会话，点击“新会话”才另建会话；回复进行时不能切换。人格的专用对话模型优先于工作空间模型，可通过「编辑人格」调整。没有选择的用途不会自动使用第一条连接。Embedding 当前提供配置、绑定与接口测试，向量召回尚未接入；当前记忆使用本地全文检索；重排序、图像和语音在模型页明确标注「未接入」。

密钥从不回传到浏览器；编辑时留空保留，勾选清除才删除。更换带密钥连接的 API 地址或协议时需要重新输入或明确清除密钥。保存采用原子替换与版本校验；不同页面或外部文件编辑冲突时会提示刷新。旧版 `providers[].model` 会兼容迁移，第一次保存时写入新的 `models` 和 `model_bindings` 结构。旧配置若共用连接，会明确提示地址、密钥等字段的影响范围；新建配置使用独立连接。

插件可显式调用 `ctx.llm.chat({ model: '<模型配置 ID>', messages })`，模型 ID 对应 `config.models[].id`。配置 ID 与提供方的模型名称是两个字段。

插件自行决定调用频率、是否设置费用预算及超额处理；主干不统一设置插件额度或因插件预算拦截调用。未来若接入插件用量上报，仅用于汇总展示，目前尚未实现。

插件可用 `ctx.models.list()`、`ctx.personas.list()` 获取选择项，用 `ctx.sessions.run()` 复用完整人格、会话、记忆与统计流程。注册 `ctx.web.page(path,handler,{title,settings:true,navigation:true})` 后，控制台自动展示设置按钮和侧栏入口，停用时自动撤销。消息、工具、记忆与生命周期通知通过 `ctx.on` 订阅；模型请求、工具和Web处理器接收插件取消信号。接口和可运行示例见插件扩展契约。

模型页按服务连接分组，一个连接可管理多个模型。填写连接后点击“获取模型列表”，搜索并勾选多个模型批量添加；已添加模型会标记，重复添加不会生成新记录。也可用“自定义模型”手动填写模型 ID。连接地址、密钥、代理与超时共享，模型参数与使用选择独立。获取列表不会保存连接或切换模型；支持 OpenAI 兼容 `/models`，DashScope 原生嵌入接口使用自定义添加。

## 配置与记忆

支持多供应商与多人格，Web 通过 `channels.web.persona` 选择人格。人格存放于配置指定的 Markdown 文件，首次启动创建占位人设。

人格内容中的“我”指助手自身。默认使用“此会话全部历史”：切换人格或修改设定后，当前身份立即更新，对话、短期摘要、长期概览和记忆继续共用；历史注入仍受 token 预算限制。需要隔离时可手动选择“仅当前人格版本”。每条记录保留当时的人格及内容版本，历史头像不会随当前人格一起改变。

概览与导航统一统计已启用、配置有效的对话和向量模型；运行插件数仅统计扩展插件，进入概览或插件页时同步当前状态。

每个会话使用 `memory/sessions/<id>/`：`session.json` 保存设置，`episodes/` 分段保存对话，`knowledge/state.json` 保存独立事实、认知、检索设置及用量，`summaries/` 保存摘要，`extensions/` 按需保存插件扩展。旧数据在启动时自动迁移，先创建带 SHA256 清单的备份到 `backups/memory-migration/`。根索引保留，会话 ID 不变。

共享事实仍位于 `memory/facts.md`，只允许用户编辑。AI 的 `remember_fact` 追加和 `edit_facts` 替换仅作用于当前会话独立事实；整份正文最多 **100 个 Unicode 字符**，包括标点、空格和换行。后端、并发写入和备份恢复均检查上限；full 权限也不能绕过。每个新会话独立事实为空，保留最近20个版本供用户恢复。会话 off 始终禁止工具；审批队列仍未接入。

“记忆管理”提供文件数量、占用和更新时间，支持共享事实编辑/去重、会话全文搜索与分页浏览、摘要查看，以及本机备份与恢复。事实保存带版本校验，防止覆盖聊天工具或另一个窗口的新写入。单次保存最多 32 KiB，每行最多 2000 字。

备份保存到 `backups/memory/`，包含记忆目录中的人格文件；不包含模型配置或密钥。恢复先校验内容并自动备份当前目录，失败回滚，进行中的对话会阻止恢复。旧格式备份在暂存区迁移成功后才安装。备份和恢复暂存目录均不进入 Git。

长期召回采用本地中文分词、少量别名和词频/鲜活度排序，默认最多6条、800估算token；普通经历默认30天半衰期，淡忘不删除原文，明确检索历史不受时间降权。可以置顶、归档、恢复或明确分享到已加入的空间；默认不检索其他会话。Embedding仍是可选的后续扩展，目前不调用向量接口。

短期压缩只在历史预算不足时于回复前生成最多 200 个 Unicode 字符的摘要，不提炼认知。长期范围累计至少 10 条未处理消息后，可在回复后生成最多 200 字的概览及最多 2 条有来源的认知，每条最多 80 字；长消息分片处理，两类整理分别保存进度。每轮最多一次整理模型调用，短期压缩优先，不启动空闲循环。短期请求最多 400 输出 token，长期请求最多 1000；两类共用每会话每天默认 20,000 估算 token（UTC 日重置），设 0 停止自动整理。聊天累计单独统计，记忆整理累计包含短期与长期，未知用量标明，不混入最近请求的上下文占用百分比。

旧正数 `recent_lines` 已废弃，不再限制为最近 30 条；旧值 0 迁移为关闭历史注入。旧 `include_summary=false` 在没有显式长期设置时迁移为关闭长期整理，新开关可独立保存。关闭长期整理只停止后续提炼，已有记忆仍可召回，带入历史时仍可使用已有长期概览。短期使用 `s_` 摘要键，长期保留兼容的 `p_` 键；旧摘要和认知保留到后续有效更新，旧概览注入时最多 200 字。整理日志区分 `short` / `long` 模式。

同一次整理可根据新证据修订或合并相关旧认知；旧版本保留并退出普通召回，无法确定的判断标记待复核。最多带入4条相关旧认知，不扫描全部历史，也不另开反思循环。记忆页可查看修订依据、确认待复核记录或撤回最新修订；共享事实权限和独立事实100字上限保持不变。

插件通过受限 `ctx.memory` 接口记录真实经历、注册扩展类型和保存状态。核心不内置意图或主动调度；只有安装相应插件才有这些扩展。插件停用后其扩展不再自动召回，已发生的通用经历保留。宿主插件是受信任代码，不是操作系统沙箱；禁止插件绕过服务直接写记忆目录。

日志输出到启动窗口、按天追加的日志文件和 Web 日志页。默认文件保留 14 天，Web 缓冲 1000 行。密钥会脱敏。

## 插件

插件开发由独立会话负责，本体维护会话专注核心。新插件会话先读本机 `docs/HANDOFF-PLUGINS.md`，其中包含实际接口、生命周期、设计稿差异、常见坑和专项测试流程。

默认 `plugins/` 只用于安装实际使用的扩展。`hello` / `hello/extra` 是开发示例，保存在 `examples/plugins/hello/`，不会随启动自动加载。它演示工具注册、父服务继承和子插件独立启停。需要体验时，将示例的 `index.ts`、`plugin.yaml` 和 `sub/` 复制到 `plugins/hello/` 后重启；类型导入改为 `../../core/context.ts`，子插件改为 `../../../../core/context.ts`。示例测试只将这份代码复制到临时工作目录，不加载本机的实际插件。任何 `data/` 都是本地数据，不应复制到示例或提交。

`plugins/<id>/plugin.yaml` 声明 id、name、description、version、depends 和 sub，`index.ts` 导出 `apply(ctx)`。工具、事件与资源通过 `ctx.tools.register`、`ctx.on`、`ctx.effect(() => cleanup)` 注册。父插件可用 `await ctx.plugin(await import('./sub/extra/index.ts'))` 显式加载导出 `id` 的子插件；省略显式加载时按 manifest 的 `sub` 自动扫描。子插件可以继续嵌套。

根插件服务跨根共享；子插件服务仅对本子树可见。`ctx.get(name)` 追踪依赖，缺失时抛错；`ctx.get(name, false)` 为可选查询。卸载时清理资源及工具，父停级联子停，内置插件不可卸载。插件数据通过 `ctx.config()` 读取，`await ctx.config.save(filename, value)` 原子写入本插件 `data/`。无效配置使用空默认值并记录警告。

控制台的启用/停用选择原子保存在本机 `config/plugins.json`，重启保持。新安装插件默认启用；停用的插件仍可在管理页看到，重载不会重新启用它。父插件或依赖暂不可用时显示“等待依赖”，不会覆盖用户原来的开关选择；依赖恢复后自动恢复原本启用的插件，明确关闭的子插件保持关闭。启用子插件前需先启用父插件。启动会重试依赖已经就绪的等待插件，不因扫描目录顺序误留停用状态；缺失或循环依赖继续等待。启停文件损坏时保留原文件并阻止加载扩展，修复后重启；不会按“全部启用”静默覆盖。此文件仅由核心管理，不属于插件自己的 `data/` 配置。

插件是可信的进程内代码，隔离指受管理生命周期与捕获边界中的异常处理。插件不得创建未登记资源或绕过上下文直接执行异步副作用。

新平台和业务通过插件扩展，不在主干添加平台专属判断。渠道可声明 `name`；工具、能力经历和扩展记忆可声明 `origin: { platform, action }`，实际插件归属由核心填写。来源会随当前对话、历史、检索和摘要传给模型，同一会话允许混合来源，外部内容不自动成为用户观点。具体字段、长度及旧数据兼容见 [渠道接口](architecture/CHANNELS.md) 和 [记忆说明](architecture/MEMORY.md)。

## 验证

使用 Node 24 执行 `npm test` 和 `npm run check`。`node tests/acceptance.ts` 在核心已监听 9270 时进行真实供应商验收（会消耗少量 token，并写入带“验收测试”标记的记忆）。报告和证据在本机 `docs/M0-REPORT.md`、`docs/acceptance/`。

本机需求文档：`docs/HANDOFF-CODEX.md`、`docs/CORE-DESIGN.md`、`docs/PLUGIN-SPEC.md`。通用文本渠道与本地长期检索记忆已实现；QQ等具体平台插件、审批流 UI、插件上报用量的汇总展示仍留待后续。控制台改造记录和截图见 `docs/CONSOLE-REPORT.md`、`docs/console-redesign/`。

`docs/`、`memory/`、`logs/`、`config/`、`runtime/` 和插件 `data/` 均不提交。公开配置模板不预选任何提供商或模型。
